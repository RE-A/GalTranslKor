# 프런트엔드 언어 리소스

이 Fork의 기본 언어는 `ko`이며 `ko`, `zh-CN`, `en`을 지원합니다. 화면 언어는 별도의
`galtransl.ui.language` 환경설정에 저장되며 프로젝트의 원문 언어, 대상 언어, 모델 프롬프트를 바꾸지 않습니다.
저장소를 쓸 수 없어도 현재 세션에서는 전환할 수 있고, 전환해도 앱을 다시 마운트하거나 양식을 비우지 않습니다.

## 번역 인수인계

`locales/zh-CN/*.json`이 원본(키의 기준)입니다. 기존 화면 문구를 유지하며, 원래 영어였던 라벨도 그대로 둡니다.
`locales/en/*.json`과 `locales/ko/*.json`은 같은 키 구조의 번역입니다. 한국어가 없거나 비어 있으면
영어, 그다음 중국어 순으로 항목마다 대체되고, 영어가 없으면 중국어로 대체됩니다.
영어와 한국어 문구는 모두 채워져 있으며 중국어를 번역 리소스에 그대로 복사하지 않았습니다.

리소스는 `common`, `settings`, `projects`, `config`, `agent`, `plugins`, `errors`로 나뉩니다.
키는 고정 식별자이므로 문구를 고치거나, 페이지 줄 번호가 바뀌거나, 번역 내용이 바뀌어도 이름을 바꾸지 마세요.
`resources.ts`는 중국어 리소스에서 `TranslationKey`를 만들며, 모르는 키는 TypeScript 오류가 됩니다.

## 문구 규칙

- `{{name}}`, `{{count}}` 같은 이름 있는 보간은 이름을 유지해야 하며 위치는 바꿀 수 있습니다.
- `count`가 있는 수량 메시지는 `_one`과 `_other`를 둡니다. 영어 단수와 복수를 각각 쓰고,
  중국어와 한국어는 두 항목에 같은 문구를 씁니다. 수량 변화가 필요 없는 메시지는 일반 키를 씁니다.
- 서식 있는 텍스트는 `<0>...</0>` 같은 구성 요소 자리표시자를 씁니다. 위치는 바꿀 수 있지만 짝을 이루는 표시와 번호는 유지합니다.
  구성 요소는 `UiTrans`의 `components`가 제공하며, 리소스에 HTML 속성이나 스크립트를 넣지 않습니다.
- 서로 다른 언어의 문장을 이어 붙이지 마세요. 가능하면 문장 전체와 매개변수를 리소스 하나에 넣습니다.
- 기술 식별자, 설정의 실제 값, 사용자 내용, 백엔드 원본 오류와 로그, 모델 출력은 번역하지 않습니다.
  에이전트 권장 지시와 번역 지침 예시도 모델 입력이므로 원문을 유지합니다. 파일 이름(예: `Basic.md`)과
  백엔드 문제 이름(예: `残留日文`)처럼 실제 값과 일치해야 하는 문구도 그대로 둡니다.

## 새 문구 추가

1. 중국어 리소스에 의미 있는 키를 추가하고, 영어·한국어 리소스의 같은 위치에 번역을 추가합니다(아직 없으면 빈 문자열).
2. React 구성 요소는 `useUiLanguage()`로 전환을 구독하고 `t(key, values)`로 렌더링합니다.
   React가 아닌 모듈은 `i18n/core`의 같은 `t`를 씁니다. 모듈 수준의 표시 정의는 키나 지연 getter를 쓰고,
   모듈을 가져올 때 번역문을 계산하지 않습니다. 표시 결과를 담은 `useMemo` 의존성에는 현재 언어가 있어야 합니다.
3. 계속 표시되는 안내는 `message(key, values)`로 저장하고 `useMessageState` 또는
   `useFeedbackState`로 렌더링할 때 해석합니다. 백엔드 원본 문구는 일반 문자열로 둡니다.
4. 설정 필드는 `labelKey`, `descriptionKey`, `placeholderKey`를 씁니다. 선택지는 `value`와 `labelKey`를
   따로 정의하고 `value`만 설정에 다시 씁니다.
5. 내장 플러그인 리소스는 `plugins:builtin`에 있습니다. `plugin-map.json`은 원래 플러그인 식별자, 설정 키,
   선택지 실제 값으로 리소스 키를 명시적으로 연결합니다. 선택지 값은 숫자, 불리언, 빈 문자열일 수 있으며,
   임의의 선택지 값을 점으로 이은 키에 넣지 마세요. 모르는 플러그인, 필드, 선택지는 백엔드 메타데이터를 그대로 씁니다.

## 검사

`desktop` 폴더에서 실행합니다.

```sh
npm run i18n:check
npm run i18n:check -- --pending
npm run test:i18n
npm test
npm run build
```

리소스 검사는 값 종류, 모르는 키, 채워진 영어·한국어 번역의 보간과 서식 표시를 확인하고, 채우지 않았거나 빠진 항목을 보고합니다
(`ko/` 접두사가 붙은 줄이 한국어). 빈 번역 값은 검사나 빌드를 실패시키지 않지만 `--pending`이 목록을 보여 주며,
`npm run test:i18n`은 영어와 한국어 리소스에 빈 값이 없어야 통과합니다. 소스 파일에 남은 중국어는
`audit-exclusions.json`에 기록하고 각 항목이 제외 대상인 이유를 적어야 합니다. 새 화면 문구는 언어 리소스에 넣으세요.

원본 테스트는 중국어 화면 문구를 검증하므로 테스트 로더(`tests/helpers/load-typescript.mjs`)는 저장된 언어가 `zh-CN`인
기본 localStorage를 제공합니다. 한국어 기본값과 대체 순서는 `tests/i18n.test.mjs`에서 따로 검증합니다.

오프라인 UI 스모크 테스트는 모의 API로 설정 전환과 새로 고침, 탐색, 프로젝트 설정, 플러그인, 에이전트, 편집 초안을 확인하며
실제 번역, 모델 요청, 유료 API 호출은 하지 않습니다.
