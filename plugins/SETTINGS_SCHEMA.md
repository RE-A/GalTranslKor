# 플러그인 설정 표시 설명

파일 플러그인, 텍스트 플러그인, 문제 플러그인 모두 YAML 최상위에 선택 항목 `SettingsSchema`를 둘 수 있습니다. `Settings`와 같은 키를 쓰며, 화면 표시 방식과 선택적인 옛 설정 경로를 설명합니다. 새 프로젝트 마법사와 프로젝트 설정 화면이 이 설명을 함께 씁니다.

```yaml
Settings:
  engine: ""
  timeout: 300

SettingsSchema:
  engine:
    label: 스크립트 엔진
    description: 보통 자동 인식을 쓰고, 인식에 실패할 때 직접 지정합니다.
    options:
      - {value: "", label: 자동 인식}
      - {value: bgi, label: BGI / Ethornell}
  timeout:
    label: 처리 제한 시간(초)
    description: 파일 하나를 처리하는 최대 시간.
    advanced: true
    min: 1
    step: 1
```

- `label`, `description`: 사용자에게 보이는 이름과 사용 설명. 원본은 중국어를 권장하며, 이 Fork에서 새로 만드는 플러그인은 한국어로 써도 됩니다. 내장 플러그인의 화면 번역은 `desktop/src/i18n/plugin-map.json`과 언어팩을 따릅니다.
- `options`: 드롭다운 선택지. 항목마다 `value`와 `label`을 가집니다. 값의 종류는 `Settings` 기본값과 같아야 하며 문자열, 숫자, 불리언을 지원합니다. 숫자 선택지는 저장 후에도 숫자입니다.
- `advanced: true`: 기본으로 접혀 있는 "고급 설정"에 넣으며 펼치면 편집할 수 있습니다. 접어도 저장된 값은 지워지지 않습니다.
- `placeholder`: 텍스트 입력 안내.
- `secret: true`: 문자열을 비밀번호 입력란으로 가려 표시합니다. 저장 방식은 그대로 프로젝트 설정이며 암호화 저장을 뜻하지 않습니다.
- `multiline: true`: 문자열을 여러 줄로 편집합니다. 정규식 결합 형식과 줄바꿈 구분자에 알맞습니다.
- `min`, `max`, `step`: 숫자 입력 제약. 플러그인은 실행 시점에도 값을 검사해야 합니다.
- `legacy_path`: 문제 플러그인은 옛 프로젝트 설정 경로(예: `problemAnalyze.avgSentenceLengthThreshold`)를 선언할 수 있습니다. 설정값 우선순위는 플러그인 기본값, 옛 설정값, 프로젝트 플러그인 덮어쓰기 값 순이며, 데스크톱 앱과 에이전트도 같은 순서를 쓰고 새로 편집한 값은 `plugin.<모듈이름>.<설정키>`에 기록합니다.

설명을 선언하지 않은 옛 플러그인은 기본값 종류에 따라 원래 컨트롤을 만들고 원래 키 이름을 표시합니다. 순서는 `Settings`의 키 순서를 따르며 일반 설정과 고급 설정을 따로 배치합니다. 옛 프로젝트에서 선택지 목록에 없는 값도 사용자가 다른 선택지를 고를 때까지 표시되고 유지됩니다. 설정 설명을 새로 추가할 때 프런트엔드 구성 요소를 고칠 필요는 없습니다.

배열 설정에 `options`를 선언하면 화면에 여러 개를 고르는 체크박스가 나오며, 선택지 종류는 기본 배열의 첫 항목으로 판단합니다(빈 배열은 문자열). 저장값은 그대로 배열입니다. 객체 설정은 JSON 편집기를 쓰며, 올바른 객체일 때만 설정을 갱신하고 형식이 틀리면 알림을 띄우고 마지막으로 올바른 값을 유지합니다.
